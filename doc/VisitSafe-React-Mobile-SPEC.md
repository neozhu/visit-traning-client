# VisitSafe React 手机端开发规范

## 目标与范围

依据既有业务需求、中文文案和登记—培训—考试—记录流程，开发独立 React 手机网页。只针对现代手机浏览器，不开发桌面布局。本轮是完整、可交互的本地演示应用，使用模拟课程、视频和浏览器本地持久化；真实认证、跨设备共享、后台审批和门禁属于后续 API 接入范围。

应用位于 `web/`，图标、插图和短视频位于 `web/public/assets/`。根目录提供启动、构建和测试入口；业务与浏览器测试全部针对 React 应用。旧客户端代码、配置、依赖及专用工具已按用户要求移除，历史业务规格和视觉参考保留。

## 人员、车辆与培训解耦目标（2026-10-16）

以下是本次确认的目标规则，React 对独立人员、独立车辆、共享培训的数据层适配及后端接入尚未实现；实体及关联设计见 [后端 SPEC 第 4、6 节](VisitSafe-Backend-SPEC.md)。本次不改变 React 访客及施工申请的操作顺序：登记信息—访问区域—确认提交—本申请培训任务—视频—考试—结果。独立提前培训是补充路径，不是提交申请的前置步骤，也不要求用户先去后台建档或选课。

- 去除首尾空格后的姓名＋手机号唯一定位人员档案，同一组合多次来访复用 ParticipantId。登记可带入已有资料，本次确认的人员资料另存申请快照，历史申请不随档案修改。
- 规范化车牌唯一定位独立 Vehicle，同一车牌跨申请复用 VehicleId，可带入默认运输单位；通过 VisitApplicationVehicle 保存本次车牌、运输单位快照。申请人员及车辆关联均不保存 SortOrder；运输单位不参与车辆匹配，本次修改不自动更新档案或历史申请，车辆仍不关联人员。
- 车辆本次实际进出厂时间及操作人保存到 VisitApplicationVehicle.CheckedInAt、CheckedInById、CheckedOutAt、CheckedOutById，时间与后台登录用户标识成对保存，新关联四个字段初始为空，不沿用其他申请或人员审计。车辆实体及种子已同步，通行操作与写入接口仍待明确，本次不增加前端操作页面。
- 培训记录独立归属于人员和课程，后台用户可选择课程并发送给 Participant，按统一规则创建或复用培训任务。React 学习人员输入姓名（Participant.Name）＋手机号找到本人任务并完成培训，无须先申请；这里的姓名不是后台登录账号的 UserName。本版不增加 React 自主选课目录，发送课程指后台分配任务，短信等额外通知渠道另行定义。
- 提交时仍按登记类型＋区域确定必修课程，再逐人逐课程处理：有效通过结果免训；已有未完成任务继续学习；没有可用记录则新建任务并正常开始学习；过期课程需要新的培训轮次。不能把“存在记录”等同于“已有效通过”。
- 实际通过后的课程有效期继续保留，每门课程分别保存通过时间与有效截止时间。提交关联不重新考试、不延长有效期；后台按人员＋课程查询实际通过结果，并在实际进厂时重新校验。
- 同一实际任务被多张申请使用时，共用视频进度、考试和有效期；申请各自保存必修课程关联。申请结束不删除独立培训，历史申请入口关闭后仍可从本人学习入口使用已分配任务。
- 申请也可由有创建权限的公司内部用户在后台创建，初始普通访客、物流车辆及施工人员均支持；内部提交者与实际来访人员分别记录。React 保留现有登记和学习入口，内部创建的申请不要求来访人员再次提交；没有有效培训记录时，仍可使用现有任务页或继续学习入口完成培训。任务访问授权及 API 接入另行明确。
- 内部创建时不确认访客须知，保存本申请须知快照并允许审批正常进行。用户在 React 申请入口打开尚未确认的申请时，先弹出本申请须知，确认成功后继续；进厂前服务端必须检查已确认。独立培训入口不受申请须知确认限制。
- 审批规则已确认为每条任务一位审批人，业务与全部区域审批并行，任一任务驳回则整单驳回并取消剩余待办。

下文任务及数据约束中的解耦要求属于待实现目标，不表示当前浏览器演示已完成数据层适配。此前 v1 到 v2 的缓存清除描述仅说明原演示规则，本次模型变更的旧缓存处理需另行制定。

## 技术与视觉

- React、TypeScript、Vite、Ant Design Mobile、Tailwind CSS、React Router，使用当前稳定版本并锁定依赖。
- Ant Design Mobile 负责表单、选择器、弹窗、提示及导航，Tailwind 负责布局；业务组件使用少量独立 CSS。
- 保留科技蓝 `#246BFD`、标题色 `#192B43`、背景 `#F5F7FB`、白色卡片和 14px 圆角；使用系统中文字体和既有 SVG 图标。
- 适配手机宽度 320–430px，支持自然滚动、底部安全区与键盘。按钮可触摸区域不少于 44px；字段有可见标签，错误信息靠近字段。

## 页面与交互

1. 首页：学习培训、普通访客、物流车辆、施工人员四个入口，继续未完成培训入口；底部首页／我的导航。
2. 登记及须知：React 外部登记仍在提交前确认本类型须知，弹窗打开后倒计时 3 秒，倒计时结束且勾选同意后才可确认继续；弹窗适配手机宽度、正文 16px，短屏可内部滚动。登记信息／访问区域／确认提交三步，草稿在刷新及重新进入后保留。后台内部创建的申请无需重新登记，React 打开时若尚未确认，展示创建时保存的须知标题和正文快照，沿用同一倒计时及勾选交互；服务端保存首次确认时间后继续申请详情或本申请学习。已确认的申请不重复弹出，不覆盖首次确认时间；未确认不影响审批，但不能进厂，也不阻止从独立入口学习已分配任务。
3. 人员与车辆：访客填写姓名、手机号、单位；施工填写姓名、手机号、工种并继承施工单位。当前本地演示的物流仍含车辆、司机及运输单位录入；后端接入目标按后端 SPEC 使用独立人员及车辆档案，申请通过各自关联保存本次资料快照。车辆按规范化车牌复用，仅保存可选司机姓名 DriverName，不关联 Participant，不从车辆创建培训人员。访客与施工支持选填随行车牌。增、改、删、取消操作完整，车牌支持七／八位自定义键盘；本次只澄清旧演示与目标规则，不改动页面实现。
4. 任务：提交访客或施工申请后仍进入本申请任务页，展示人数及课程进度，支持选择个人或全部人员。按姓名＋手机号定位人员档案，再按课程关联有效结果、已有未完成任务或新建任务；没有可用培训记录时正常开始视频和考试。有效结果显示“有效期内免训”、真实通过时间和有效截止，计入个人合格进度；不能把一人的结果复制给其他人。
5. 继续学习：姓名＋手机号精确定位本人当前需要学习的任务，包含没有申请的已分配任务；同一任务被多个申请引用时共用进度、只展示一份待学任务，可展示关联申请。按本次申请或独立分配的当前任务筛选待学列表：满足本次免训条件且没有待学轮次的课程不要求重复学习；过期结果不能免训，有培训需求时生成或关联新轮次，重新完成视频和考试。需要学习的新轮次必须正常显示，不能因同课程其他轮次有通过结果而隐藏；查询不创建登记，也不作为身份认证。
6. 视频：真实播放本地短视频，完成全部片段后才能考试。播放错误明确提示，允许用户主动开启演示计时完成该片段；返回及刷新按已有任务恢复进度。
7. 考试：当前演示每门五道单选题，每题 20 分，80 分通过，15 分钟；后端接入目标为恰好五道四选项题，可混合单选和多选，题型、及格分及考试时长按课程快照。单选选答后自动进入下一题，多选按完整选项集合评分，不因选择单个选项提前判定完成；支持修改、答题卡和最终答案评分，主动交卷须答完，到期允许未答题并自动交卷。多选全选正确才得分，不设部分得分。
8. 结果：成绩、通过状态、错题解析、重新考试及个人培训凭证。失败重考保留本轮视频完成情况，新建考试并使用新的答卷与截止时间；已通过且仍有效不重考。免训查看关联的真实通过记录和原有效期，不生成新的视频进度或成绩；旧学习／考试链接不能绕过免训或继续已过期轮次。多个申请打开同一未交卷考试不重置其开始时间、截止时间及答案。
9. 记录：搜索姓名、单位及车牌，查看申请详情、当前个人合格进度，继续学习及确认删除的操作入口保留。解耦后的本地演示删除仅移除本申请及其展示关联，保留独立人员、车辆档案、真实培训和考试，其他申请继续使用；不再要求先删除使用同一结果的其他申请。正式后台申请删除权限与历史关联保留方式仍以后续规格为准。

## 数据约束

- 预约日期不能为空、必须是真实日历日期且不早于今天；到访时段和事由必须来自给定选项。
- 三类业务信息沿用现有必填要求。访客／施工同一申请内手机号唯一，物流车牌唯一。当前演示按同一姓名＋手机号归并司机课程属于旧数据规则；后端接入后按独立 Participant 分配课程，车辆不参与人员归并。
- 人员档案按去除首尾空格后的姓名＋手机号组合唯一；档案复用与同一申请内的人员去重分别校验。每次申请保存本次姓名、手机号、单位、工种及选填资料快照；施工单位同步只影响本次草稿，不自动修改全局档案或历史申请。
- 车辆档案按规范化车牌全局唯一，同一申请不得重复关联同一车辆；服务端重新执行车牌规范化与校验，并发不创建重复档案。每次申请保存本次车牌及运输单位快照，车辆及本次运输单位必填要求来自 VisitType，档案默认值不能绕过本次必填校验。
- 培训课程通过模拟“登记类型＋区域”组合配置匹配，多个区域课程合并去重；无有效区域或缺少匹配配置时不能提交。
- 每门模拟课程独立配置 trainingValidityDays，默认 60 天，实际通过后保存有效截止；修改课程配置不追溯已有结果。复用结果也必须在预约日开始时仍有效；过期重训保留旧记录和原期限，不沿用旧视频进度。
- 有效结果要求真实考试通过且满足 `completedAt <= 当前时间 < validUntil`，申请提交还要求截止时间晚于预约日开始。按人员＋课程匹配；部分课程有效时只免训有效课程，其他课程继续或新建任务。
- 过期后重新完成本轮全部视频和考试，新通过时重新计算有效期；保留原轮次及原截止时间，不沿用过期轮次的视频进度。待学列表按当前任务是否需要学习判断，不能按课程是否曾经通过过滤。
- 申请关联的课程集合在提交时确定；按本申请已关联轮次选择当前记录，旧轮次不能掩盖当前任务未完成或过期。申请只引用真实培训记录，不创建免训副本；后续其他申请分配的新轮次不自动替换本申请的使用依据。
- 同一草稿重复提交返回同一申请；持久化失败不报告提交成功，也不改写内存状态。
- 考试截止时间和答案持久化。离开、刷新、手机进入后台不能重置截止时间；返回页面按绝对时间计算并交卷。
- 内部创建申请时 NoticeAcceptedAt 为空；React 申请入口完成确认后由服务端保存首次确认时间，申请审批不等待确认，进厂前必须检查已确认。已有申请展示须知快照，后续须知配置修改不改变本次确认内容。
- 本地存储使用 `visitsafe.web.v2` 命名空间；新版直接清除旧 v1 登记与视频演示计时，不迁移旧数据。新数据的缺损缓存有明确恢复行为，记录仅在当前浏览器可用。
- 后端 SPEC 的动态类型、审批、实际进出厂和审计规则保留供后续接入，不模拟真实审批或通行授权。

## 验收

- 三类登记均走通，访客／施工随行车辆可编辑及取消；刷新恢复草稿，错误提交保留输入。
- 多人、多课程的任务相互独立；精确查询、重载、重考、到期和删除行为有自动化测试。
- 有效历史通过可免训，新增课程与其他人员独立判断；截止时刻、逐课程期限、过期重训、复用不续期、共享记录保留及原演示缓存处理属于验收范围；本次调整仍需在数据层实现后验证，不表示已有测试已覆盖新模型。
- 手机尺寸浏览器验收首页、登记、车牌弹层、视频、考试和记录；页面无水平溢出，固定按钮不挡内容。
- React 应用业务测试、类型检查、生产构建和手机浏览器流程均通过。

本次解耦的待实现验收：

- 首次提交访客或施工申请且没有培训记录时，仍能从提交成功进入申请任务页，正常完成视频、考试及结果；页面步骤和个人／全部人员学习操作保持原样。
- 提前独立通过的课程在有效期内被申请直接使用；已过期、未完成或从未分配的课程不能免训。各课程原通过时间及截止时间保留，关联不续期。
- 已有未完成任务在提交后继续原视频和考试进度，同一任务关联多张申请不复制进度或考试；后台提前分配但没有申请的任务也能通过本人学习入口查询。
- 内部后台创建的申请使用相同课程及有效期规则，来访人员可以沿用 React 学习流程，不需要重复登记；内部创建不自动免训或审批通过。
- 后台选择课程发送给 Participant 后，前端输入该人员姓名＋手机号即可查到待学任务并完成；没有申请也可学习，不显示自主选课目录，不要求后台账号登录。
- 内部申请尚未确认须知时可以正常审批；React 申请入口先确认本申请须知再继续，重复打开不重复确认。审批及培训均通过但须知未确认仍不能进厂；独立培训仍可学习。
- 再次登记复用人员档案并带入已有资料，本次申请保存独立快照；删除本地演示申请不删除共享人员、培训和考试。
- 同一规范化车牌再次登记复用车辆档案，运输单位变化不产生新车辆或改写历史快照；同一申请重复车辆被拒绝，删除本地演示申请不删除共享车辆档案。以上为待实现目标，不表示已有页面支持车辆复用。
- 以上场景需在后续实现时验证；本次规范更新不代表代码、测试或浏览器验收已完成。
