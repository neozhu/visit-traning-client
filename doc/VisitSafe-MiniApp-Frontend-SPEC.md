# VisitSafe 微信原生小程序前端 SPEC

更新日期：2026-10-11。本文记录当前前端规则和验收要求。

## 技术与范围

- 微信原生小程序：TypeScript + WXML + WXSS，使用 Mock Data 和本地 Storage。
- 不开发后端、不接入真实 API、不使用云服务；登记、编辑、删除、学习、答题和查询必须实际可交互。
- 沿用现有模块结构和企业界面，后续可替换存储适配层接入共享数据。
- 本次调整学习入口与人员任务归属；其他三个登记入口的流程节点、课程匹配、视频要求、考试规则和结果流程保持不变。

## 首页四个入口

| 入口 | 用途 |
| --- | --- |
| 学习培训 | 按登记姓名＋手机号查找本人已有的未完成任务，继续学习和答题 |
| 普通访客 | 完成访客须知、人员登记、区域选择和确认提交，生成各人的任务 |
| 物流车辆 | 完成访客须知、司机及车辆登记、区域选择和确认提交，生成各位司机的任务 |
| 施工人员 | 完成访客须知、施工人员及工种登记、区域选择和确认提交，生成各人的任务 |

学习培训入口不新建独立培训登记，不要求再次确认须知或选择区域。首页“继续未完成的培训”进入同一查询入口。

## 首页视觉

- 保留现有页面结构、四个入口、工厂插画、原生底部 TabBar，不因样式调整改变业务或导航。
- 使用科技蓝 #246BFD、深海灰标题 #192B43、页面背景 #F5F7FB，呈现简洁、清晰、克制的企业界面。
- 降低 Hero 高度，保留工厂插画和浅蓝灰渐变背景，突出品牌标题。
- 四个入口保持纵向排列，使用白色或浅色卡片，以彩色图标和柔和图标背景区分业务类型。
- 卡片使用 12–16px 圆角、细边框和极轻阴影。区块文案为“请选择办理事项”。
- 品牌标题 30–34px，区块标题 18–20px，入口标题 17–18px，描述 12–13px。
- 保持清晰的触摸区域、合理间距和安全区留白；小屏允许自然滚动，大屏保持内容宽度和字体层级。
- 所有样式使用原生 WXSS，不引入额外 UI 框架。

## 登记与原有节点

普通访客、物流车辆、施工人员保持以下流程：

入口 → 勾选访客须知 → 人员或车辆信息 → 访问区域 → 确认提交 → 培训任务 → 视频学习 → 在线考试 → 结果／错题解析 → 培训完成 → 我的记录。

- 列表支持添加、编辑、确认删除，关闭编辑弹窗不保存尚未提交的修改。
- 普通访客和施工人员登记姓名、手机号和单位；施工人员额外填写工种。物流登记车牌、司机姓名、手机号和运输单位。
- 保留必填、手机号、重复人员、车牌和区域校验。重复提交同一草稿不得重复创建申请单。
- 访问区域可多选，生产区、研发区、非生产区匹配原有课程；物流额外匹配交通安全，施工额外匹配施工安全。
- 确认页显示每人必修课程和全单个人课程数量，提交后进入该申请单的任务页。

## 每个人独立学习

每位人员都有独立的一组任务，每组包含申请单匹配的全部课程。课程任务关联申请单、人员和培训方案，三者共同确定归属。

- 普通访客与施工人员按登记人员生成任务，物流按司机生成任务。
- 同一申请单中姓名和手机号都相同的司机，登记多辆车辆时只生成一套个人课程。
- 每位人员的视频进度、考试答案、截止时间、成绩、通过状态和重考进度分别保存，不能因一人完成而改变其他人的进度。
- 任务页显示人员和课程完成数，支持“全部人员”依次学习，也支持选择某个人学习。同一手机可供多人依次操作，每人仍需独立看视频和答题。
- 视频、考试、结果、完成页和培训记录标明人员姓名及脱敏手机号。
- 全部人员通过全部必修课程后，申请单沿用“已完成”状态；任何一人有课程未通过，申请单仍为“培训中”。不增加审批、入场或离场节点。

示例：登记张三、李四、王五，选择两门课程。生成三人的任务组，共六项个人课程任务。张三通过两门后，人员进度为 1/3，课程进度为 2/6；李四、王五仍未开始。三个人全部通过后整单完成。

## 姓名＋手机号继续学习

学习培训入口 → 输入登记姓名和手机号 → 查询本人待完成培训的申请单 → 选择申请单 → 本人课程任务 → 继续视频学习和答题。

- 两个字段必须同时匹配，允许去掉输入首尾空格；不得只凭姓名或手机号匹配。
- 姓名必填，手机号遵循登记时的 11 位有效手机号校验。校验失败保留输入，并提示具体错误。
- 查询只读取已有任务，不创建申请单、不创建重复任务、不重置进度。
- 同一身份在多张申请单中有未完成任务时，分别显示类型、登记时间、访问区域和本人的待完成课程数。
- 从查询进入申请单后，仅显示匹配人员的课程，不显示其他人员的学习选择项。
- 已通过课程保留结果，视频和考试中的任务恢复原状态。本人全部课程通过后，该申请单不再出现在本人的待完成查询中。
- 查不到任务时提示核对登记信息，说明尚未登记或已经全部通过也会出现空结果。
- 删除申请单同时删除关联任务，查询和旧链接不能继续这些任务。

## 视频与考试规则

- 沿用本地短版演示视频，每段六秒。必须完整观看本人的全部视频后才能考试。
- 加载失败时沿用六秒演示倒计时，未结束不能计入进度；重复错误或返回页面不能重启已启动的倒计时。
- 每门课程五道单选题，每题 20 分，80 分通过，限时 15 分钟。演示正确答案为 A、B、C、A、B。
- 选完自动进入下一题，答错提示并在答题卡标记；允许返回修改。最后一题不自动交卷，按最终答案评分。
- 主动交卷必须全部答完；到期按已有答案自动评分，未答题得零分。离开和重载保留答案与截止时间。
- 未通过可查看错题并重考；重考只重置本人的该门课程答案和计时，保留本人视频完成状态。

## 本地数据与限制

- 沿用 visitsafe.demo.v1 存储，保存草稿、申请单和人员课程进度。重载后保持一致，写失败不得报告提交或学习成功。
- 本次按用户要求清空开发者工具中当前小程序的旧记录后验收。应用启动不自动清空记录。
- 有明确人员归属的旧任务保留进度，只合并同一人员、同一课程的重复记录。单人旧共享任务可归给唯一人员；多人旧共享任务无法确定学习人，重建个人课程，不能复制共享通过结果给所有人。
- 目前查找仅针对本设备数据，姓名＋手机号匹配不提供真实身份认证。
- 其他手机的本地存储无法读取本手机的申请单。真实的“各自手机继续同一张申请单”需要后续单独确定并接入共享数据服务，不属于本次修改范围。

## 验收场景

1. 空记录从学习入口查询，显示必填校验或无待完成任务，不创建登记。
2. 普通访客登记三人，按原节点选择区域和提交，生成三人的完整个人课程并显示各人状态。
3. 在登记手机选择一人完成全部课程，另外两人的视频、答案和成绩不变，申请单保持培训中。
4. 返回首页，用另一人的姓名＋手机号查到并继续原任务；姓名或手机号错配均不能匹配。
5. 同一身份关联多张申请单时可分别选择，查询进入的任务页仅显示本人课程。
6. 物流司机和施工人员独立学习区域及专属课程；同一司机多辆车不重复生成个人课程。
7. 全部人员全部通过后整单完成，已完成人员的待完成查询为空；记录显示人员及课程完成数。
8. 视频未完成不能考试；失败重考、错题修改、离开恢复、超时评分和不同人员的计时互不影响。
9. 重载保持进度和整单状态；删除申请单后任务与查询结果消失；损坏任务不能使整单误判为完成。

运行和验证命令见 README。验收使用虚构数据，模拟器验收先备份本应用存储，结束后恢复。
